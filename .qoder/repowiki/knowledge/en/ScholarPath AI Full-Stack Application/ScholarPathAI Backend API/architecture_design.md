Single-file Express 5 application (`index.js`) serving as the sole HTTP entry point. It bootstraps middleware (CORS, JSON parsing, `multer` memory storage), validates required env vars (`SUPABASE_URL`, `SUPABASE_KEY`, `JWT_SECRET`) at startup, and configures a global `undici` Agent with connection pooling for outbound requests. Authentication is implemented via a local `authenticateToken` middleware that verifies JWTs signed with `JWT_SECRET` and attaches `req.userId`. All routes are registered directly on the app under `/api/*` and grouped by domain: auth (`/api/auth/*`), profile & CV upload (`/api/profile/*`), scholarships & universities (`/api/scholarships`, `/api/universities`), language prep guides (static in-memory lookup), attestation workflow (HEC/IBCC/MOFA step tracking), matching engine (`/api/profile/:id/match-scholarships`), shortlist, applications tracker, notifications, and placeholder endpoints for document conversion, letter generation, and chat. Data access goes exclusively through the Supabase JS client against tables `profiles`, `scholarships`, `universities`, `matches`, `shortlist`, `applications`, `attestation_steps`, `notifications`, plus Supabase Storage bucket `cvs`. Static reference data (language-prep guides, attestation authority steps) is embedded as JavaScript objects rather than fetched from the DB.
